# Agent 团队工作纪律（核心）

> 【用户裁定 2026-10-19】本文件为**团队协作操作纪律**，与 [AGENTS.md](../AGENTS.md) 互补：
> 证据分级/门禁/提交规范以 AGENTS.md 为准（单一真相源）；本文件覆盖 **agent 团队模式下的
> 分工、完成判据、Leader 唤醒规程与落库要求**。两者冲突时以 AGENTS.md 为准并 dated 更正本文件。

## 1. 团队模式

1. 按 **agent 团队模式**开发：Leader + 专职子 agent（实施 porter/analyst、复核 verifier、调研 auditor 等）。
2. **Leader 是协调者**，职责仅限：任务分派、结果检查、进度与目标对齐、纪律巡查、提交/push 收口；
   **不替代**子 agent 的实施与复核（实施 ≠ 复核不变）。
3. 任务一律走任务卡（task-NNN）：领卡 → 实施 → 对抗审查 → 通过 → 提交 push → 完成。

## 2. 任务完成纪律（每个任务，无例外）

每个子 agent 领取的任务——**不论开发任务还是调研/方案设计**——完成后必须同时满足：

| # | 判据 | 说明 |
|---|---|---|
| 1 | **对抗审查通过** | 独立复核方（不得为实施方）以证伪立场复核，verdict=**pass** |
| 2 | **测试用例通过** | 代码修改必须过测试用例（相关测试全绿，含新增回归）；文档/调研类=数字可复算 |
| 3 | 二者皆过 **才视作完成** | 任一未过 = 待审稿，不得计入进度 |
| 4 | **提交并 push** | 完成后必须 git commit + **push 到远端**；**只有推进到远端才视作进度保存完成** |

## 3. Leader 唤醒规程（强制步骤，不允许跳过）

**唤醒源**：① 10 分钟定时器定期唤醒；② 任何子 agent 完成通知；③ 任何其他方式唤醒。
**不论以何种方式被唤醒，Leader 必须按序执行以下步骤：**

0. **检查行任务（先行）**：检查已完成任务**是否已复核、是否已提交并 push**；
   若没有 → 立即补任务/补动作（补复核卡、补提交 push），保证工作纪律闭环；
   a. **确认当前工作进度与 agent 占用情况**：若不存在空闲 agent（全部在忙）→ **跳过本轮**（仅留巡查记录）；
   b. 若有空闲 agent：**重新思考当前工作方向与目标是否一致**，给出**判定理由、时间、判定人**，
      **写成证据落库**（team-ops-ledger.md）；
   c. **对齐进度与目标后分派任务**：核心原则=**在保证任务不冲突的前提下尽可能派满任务**；
      每次派任务后**必须落库**（分派人、时间、具体分派任务、理由）；
   d. **429 处理**：遇到 429 停止时**不要重派任务**，把原任务**唤醒继续**即可（避免重复/丢任务）。

## 4. 落库要求（证据台账）

- **台账文件**：[docs/findings/team-ops-ledger.md](findings/team-ops-ledger.md)（append-only，**dated 不删历史**）。
- 必须落库的事件：
  1. 每次唤醒巡查（时间、agent 占用、结论——含"跳过本轮"）；
  2. 方向判定（时间、判定人、判定结论、理由、依据的证据指针）；
  3. 每次派单（分派人、时间、任务卡号/内容、理由、预期验收）；
  4. 429/异常处置记录（时间、原任务、唤醒动作）。
- 每条格式：`## 【YYYY-MM-DD HH:MM】<事件类型>` + 正文；提交随日常 commit（不单独等批次）。
