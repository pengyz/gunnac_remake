## 0. L4 定义与判定物

| 项 | 内容 |
|---|---|
| 判定对象 | 截图**逐像素**比对：Rust 帧缓冲 vs Mesen2 `emu.takeScreenshot` |
| 判定物 | `tools/diff_visual.py` 输出（白名单外像素差异计数 + 差异图） |
| 判定式 | **白名单外像素 100% 一致**（0 容差默认）；差异二分类 = 白名单内（平台差异，豁免）/ 白名单外（FAIL） |
| 保真红线 | D4 quirks（8 sprites/scanline、闪烁、掉帧、溢出）是**保真对象不是容差来源**——出现即算真差异 |

## 1. 截图 diff 判定口径

| 维度 | 口径 | 理由 |
|---|---|---|
| **帧对齐** | 比对同一 `endFrame` 渲染完成帧（场景 DSL 采集点）；注入 **+1 帧延迟约定**（Q4，`oracle/scenarios/README.md`）下 schedule(N) == trace.held(N+1)，比对帧号两侧共用一套计数 | t28 实证 12/10 边界差异全为延迟约定问题——口径混用会产生假差异 |
| **分辨率** | **256×240 原生帧直接比对**，禁缩放/重采样进入比对层（Rust 侧渲染输出必须是 256×240 逻辑帧；窗口化/高清化属 Stage B） | 缩放引入重采样误差会污染 0 容差判定 |
| **色彩空间** | 比对**调色板索引域**（首选）或统一 sRGB 输出；Emulator 截图 RGB ↔ Rust RGB 必须走同一 NES 调色板映射表 | 见候选 W-C1 |
| **容差** | 默认 **0**；唯一例外=白名单（白名单本身就是"容差的具名化"）；不做"±1 色阶""95% 相似"类软阈值 | AGENTS.md §5：不许调阈值掩盖 |
| **时间轴** | 帧精确（无时间容差）；闪烁/掉帧相位差异=真差异（保真对象，D4） | 同上 |
| **比对范围** | 整帧（含 HUD/状态栏/边框）；分区域仅用于差异归因报告，不用于豁免 | 防"区域豁免"变相放宽 |

## 2. 视觉白名单候选清单（**只列候选，全部未启用**；启用逐条需用户确认 + commit 记录）

> 候选判据：**平台差异**（渲染路径不同但语义等价）才可入白名单；游戏行为差异（含 D4 quirks）**永不入**。

| 候选 ID | 内容 | 差异形态 | 级别 | 备注 |
|---|---|---|---|---|
| **W-C1** | NES 调色板映射表（模拟器默认 palette ↔ Rust 侧 RGB 转换） | 整帧系统性色偏 | 强候选 | 最可能需要；应先尝试**共用同一映射表**（从比对层消除差异）而非白名单化 |
| **W-C2** | 汉化字模/文本渲染字形（CHR tile 直接渲染路径差异） | 字形像素微差 | 弱候选 | 若 Rust 直接消费 CHR 应逐像素一致 → 预期**不需要**白名单 |
| **W-C3** | 字符串行尾/断行/前导零抑制渲染（bank14:D009 前导零跳位的渲染等价性） | 文本行像素差 | 弱候选 | R-money-4 已证渲染规则——先移植对齐，不预设豁免 |
| **W-C4** | 截图色彩空间/伽马（emu 输出 vs Rust 帧缓冲存储格式） | 全帧亮度偏移 | 强候选 | 与 W-C1 合并处理优先（统一色彩空间后消失） |
| **W-C5** | 精灵 0 hit / 扫描线时序造成的行分割错位（split scroll/HUD 分界） | 带状错位 | **待定** | 属 D4 保真对象（MMC3 IRQ 行为）——若 Stage A 要求一致则**不入白名单**；仅当确认为平台不可复现差异时再议 |

**明确不入白名单**（保真对象，D4）：8 sprites/scanline 溢出、闪烁相位、掉帧、数值溢出显示、
敌人/弹幕行为差异、动画帧序。

**治理流程**（启用时）：候选 → 用户确认 → `gates/visual_whitelist.json` 逐条登记（含理由+证据）→
`visual-diff` 门禁引用 → 变更单独 commit + Evidence。参考教训：
[pattern-visual-binding-needs-pixel-proof.md](../knowledge/pattern-visual-binding-needs-pixel-proof.md)
（视觉元素与数据源的绑定要像素级证明——白名单理由同样需要）。

## 3. 采集面与工具建设需求（S6 启用前置）

| # | 项 | 内容 |
|---|---|---|
| V1 | `oracle/screens/` 目录契约 | 预期图（oracle 侧）/ 实际图（Rust 侧）/ 差异图 三分目录；命名 `<场景>_f<帧>_<tag>.png` |
| V2 | `tools/diff_visual.py` | 输入两图 + 白名单 JSON → 输出差异像素计数/差异图/白名单命中归因；0 容差；exit code 裁定 |
| V3 | Rust 侧帧缓冲导出 | game-platform trait 增加 `screenshot()`（256×240 逻辑帧导出，禁缩放） |
| V4 | 场景挂钩 | DSL `assert_screen`（l5-plan §3 C5）→ 复用 `capture` 采集点 |
| V5 | 白名单 JSON schema | `gates/visual_whitelist.json`：id/理由/证据/像素区域（可选）/用户确认记录 |
