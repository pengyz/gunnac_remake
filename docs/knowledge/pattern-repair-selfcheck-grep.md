# pattern：修复自查（grep 目标行 + 新引入事实复核）

## 适用场景

任何"修复/更正/降级"类编辑完成后、提交前的强制自查。**修复 ≠ 声称修复**——
编辑器里跑了 replace 不等于目标行真的变了；改一句话常引入新数字/新事实，同样需要复核。

## 纪律（两步）

1. **grep 目标行**：修复后立即 grep 原文关键词与新文关键词各一次——
   原文关键词应 0 命中（或仅存于 dated 留档注内），新文关键词应恰在目标位。
2. **新引入事实复核**：修复文本里的每个新数字/新地址/新结论单独核对来源
   （t154 §5 正面样板：逐条挂证据指针后自检）。

## 活例（反面）

- **三轮"声称已修原地未动"**（t154 前序）：修复任务自报完成但 grep 目标行原文仍在——
  三轮返工才闭环；根因=无自查步骤，编辑器操作与产物未对账。
- **R7-1"修复引入新错"**：修复文本写了错误新数字（改动处本身成了新缺陷源）——
  只查"改没改"不查"改对没改对"。

## 活例（正面）

- t154 §5 **自查记录**：修复后 grep 双关键词留痕 + 新事实逐条复核表——复审（t158）独立验证
  R6-1..4 全落地且无新错，"自查纪律首用合格"。
