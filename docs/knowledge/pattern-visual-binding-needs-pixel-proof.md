# pattern：视觉元素 ↔ RAM 变量绑定必须像素级证明

## 现象

t18 的 N-0032 曾登记"HUD 字母位 = `weapon_slot`（$34）"（conf 80，A 级）——依据是拾取处理
`CMP $34/STA $34` 与 HUD 字母变化的同步表象。t28 确定性 run **位图解码证伪**（N-0037）：
f2220 拾『W』后 `$34=3` **且** `$0190=3`，但 HUD 行 1 字母在 f2280 仍为 **'A'**
（位图 rows 40-51，`docs/findings/orphan-run-recheck.md` §2.2）。
绑定撤回：$34 的核心事实（CMP/STA 拾取处理、死亡重置）维持，**字母位来源另考**（Q1/Q2）。

## 为什么

- 视觉元素是渲染管线**末端产物**（tile 码/精灵映射/字形表/缓存），RAM 变量是**状态**；
  两者之间可能隔着多层间接。同帧同步变化**只说明共享上游事件**，不说明同源。
- "相关性 ≠ 绑定"：绑定主张要求**分离事件**下锁定——一个变、另一个不变的场景出现后仍对应，
  才能排除共同上游。f2220 正是分离事件（$34 变、字母不变）→ 绑定死。
- 台账/rename 一旦把视觉绑定当 A 级落地，错误会传导到 spec 规则与 Rust 移植（HUD 渲染读错源）。

## 何时使用

- 任何"HUD/显示元素 X = RAM 变量 Y"的命名或规则主张前：先做**像素级证明**——
  该元素的**位图解码**（rows/cols + 帧号）与候选变量的**帧间 diff** 双向对齐，
  且经至少一个分离事件检验。
- 台账中视觉绑定类证据必须含位图解码指针（位图行区间 + 帧号），仅有"同步变化"观察的
  一律降 C 级入假设区（N-0037 形态）。
- 出现反例立即**证伪撤回**（原记录标 reverted + 追加 _todo_ 条目），不修补旧结论。
- 反例（本条教训来源）：N-0032 以同步表象立 A 级绑定 → N-0037 撤回。
