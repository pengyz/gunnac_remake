# gotcha：观测粒度伪造不变量（60 帧 probe 把错帧事件"看成"同帧）

## 现象

t22 用 **60 帧 probe 粒度**观察 f2160→f2280 区间：`$0190` 0→3、HUD 字母 F→W、`$018F` 3→4
"同步"发生——据此 R-bomb-2 立下**"三方同帧同步"不变量**。
t36 逐帧 golden（`oracle/traces/gameplay-stage1.weapons.jsonl`）证伪：**f2174**（弹数 3→4）与
**f2175**（弹种 0→3 且弹数不变；同帧 `$34` 0→3）相隔 1 帧——三个变化实际**错帧**，
"同帧同步"是采样网眼把 1-2 帧内的多个事件压进同一格伪造出来的。R-bomb-2 已按反例收窄
（弹种+HUD 字母同帧不变量保留；弹数变化=同事件簇独立维度）。

## 为什么

- 粗粒度采样把时间窗内的**共现**压成**同刻**：窗口内 N 个错帧事件在 60 帧网眼里全部"同格"。
- 窗口越大，伪造出的"不变量"越强（三变量任意顺序在 120 帧窗内都"同步"）。
- 同族陷阱：[gotcha-stack-page-game-var-watch-coverage.md](gotcha-stack-page-game-var-watch-coverage.md)
  （采样面缺陷伪装成逻辑缺陷）——一个是**时间轴网眼**，一个是**地址轴盲区**，共同点是
  **采样设计缺陷会产出看似干净的错误结论**。

## 何时使用

- 写"同步 / 同帧 / 恒定 / 同时"类不变量前，**核对观测粒度 ≥ 声明粒度**：
  probe 级观察只能声明"同窗/同簇"；"同帧"必须有逐帧 trace 支撑。
- 升级不变量前先做**反例搜索**（逐帧 diff 找错序案例），找不到才允许立不变量。
- 证伪时按 R-bomb-2 模式：原地日期更正 + 收窄声明 + 挂反例指针，不删历史主张。
- 反例（本条来源）：60 帧 probe"同步"→ 同帧不变量 → golden 逐帧断言失配。
