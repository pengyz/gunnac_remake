# gotcha：栈页游戏变量区的 watch 覆盖（勿假设 RAM = 零页 + iram）

## 现象

本作把游戏变量放在 **$0100-$01FF 栈页**：`$018E`（digit_conversion_scratch）、`$018F`（bomb_ammo）、
`$0190`（bomb_type_index）等。而采样/watch 区间惯常按"常规 6502 分区"假设只覆盖零页 $0000-$00FF
与 iram——栈页变量落在盲区。**两起同源踩坑**：

1. **t24 栈页写集误吞**：L2 对拍的写集比对漏掉栈页地址变量（断言面缺一角）。
2. **t31 跨页误映射**：`$018F`/`$0190` 被误映射为 `$008F`/`$0090`（页号看丢）——
   直接导致 t38 FA-3"武器 golden 0 行"：**根因是采样盲区，不是抽取逻辑错**；
   修复=采样面加宽（commit `aa04ecf`）后 golden 转非空且含 `kind=bomb` 事件。

## 为什么

- 6502 惯例把 $0100 页留给栈，**但 Compile 把游戏变量也放这里**——按惯例划 watch 区间必漏。
- 盲区的症状极具欺骗性："golden 0 行 / 断言 0 条 / 写集无差异"看起来像逻辑没问题、只是没事件，
  实际是**断言对象根本不在采样面里**（与粒度陷阱同族：采样面缺陷伪装成逻辑结论）。
- 跨页误映射（$018F→$008F）还会产生**错地址的假数据**，比缺失更危险。

## 何时使用

- 定 watch / `watch_range` / L2 写集 / 采样面时，**按变量地址逐页核对**：
  已命名变量先查台账地址所属页（$018E/$018F/$0190 都在 $0100 页！），勿假设分区边界。
- 见到"golden 0 行 / 断言 0 条 / 写集空"→ **先查采样面覆盖**（地址页、区间端点、watch 清单），
  再查抽取与逻辑。
- 新变量命名/引用时把页号写进台账（`$018F` 而非 `8F`），杜绝跨页误映射。
- 反例（本条来源）：t24/t31 两坑同源于"RAM=零页+iram"假设。

## 证据指针

- t38 任务输出（FA-3 根因=采样盲区、t31 跨页误映射、修复后 weapons golden 转非空）
- commit `aa04ecf`（采样面加宽）与 `b863f9f`（FA-3/FA-4 处置）
- `oracle/subroutines/README.md`（$0100 页教训入运行/覆盖表；FA-4 覆盖表 33→54）
- `data/naming/ledger.jsonl` N-0023（$018E）/N-0017（$018F）/N-0030（$0190）——三变量地址锚点
